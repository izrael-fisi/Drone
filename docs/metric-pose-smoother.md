# Metric Pose Smoother: Research Replay

Status: September 5, 2026. Implemented and tested on synthetic metric factors
using GTSAM 4.2.2 on macOS/Python 3.11. This is a real SE(3) optimization backend,
not a complete visual-inertial navigation system or flight release.

Every output declares `navigation_mode: NO_GLOBAL_FIX`,
`position_authority: false`, and `px4_external_vision: disabled`, including
numerically successful `SMOOTHED` results. No aircraft connection is opened.

## Position In The Architecture

```text
Qualified local VIO increments ------> local keyframe poses X(k)
Qualified learned 3D map-camera fixes -> map/local alignment A
                                       |
                              fixed-lag GTSAM optimizer
                                       |
                              replay-only pose + uncertainty
```

`X(k) = local_T_body(k)` and `A = local_T_map`. A map measurement contributes
`Between(A, X(k)) = map_T_body(k)`. The first local pose has a tight identity
gauge prior, which defines coordinates rather than measuring a global origin.
The separately composed raw local trajectory is never overwritten by map fixes.
The optimized local trajectory may change retrospectively; a future live local
odometry publisher must not mistake it for the uncorrected frontend output.

The implementation uses iSAM2 with QR factorization, fixed-lag marginalization,
Huber map factors, and an innovation gate. A delayed fix attaches to its original
retained keyframe, not to the latest pose. Alignment remains in the graph while
old keyframes are marginalized. A hard keyframe limit rejects overload without
silently discarding an incremental motion measurement. Solver failures latch;
recovery requires a new explicit session.

## Installation And Verification

Use a separate Python 3.11 environment. Stable GTSAM 4.2.2 requires NumPy below
2; the model-export environment may use newer Python/NumPy. Do not force these
incompatible requirements into one environment. Python 3.11 is the tested path;
availability of other platform wheels must be checked separately.

```bash
python3.11 -m venv .venv-estimation
source .venv-estimation/bin/activate
python -m pip install -e '.[estimation]' pytest
python -m pytest -q tests/test_metric_pose_smoother.py tests/test_vision_first_navigation.py
```

This does not install or benchmark anything on the Pi. Before Pi integration,
verify ARM64 wheel/build availability, runtime compatibility, and measured
latency/memory on an idle, prop-off device.

## Input Contract

Configuration is a JSON object containing `SmootherConfig` fields:

| Required field | Meaning |
| --- | --- |
| `map_release_id`, `model_release_id` | Immutable learned map/model identities |
| `calibration_id`, `vio_release_id` | Extrinsics/camera and metric frontend identities |
| `clock_id` | Shared, calibrated monotonic exposure/odometry clock |
| `covariance_model_id` | Declared uncertainty model used to produce factors |
| `body_T_camera` | Proper 4x4 camera-optical to body-FRD transform |
| `map_systematic_covariance` | Positive-definite 6x6 common map error floor |

Limits include lag, retained keyframes, odometry gap, local/map age, innovation
threshold and Huber tuning. Defaults are development settings, not flight-tuned
limits. IDs are checked for exact equality; this does not itself verify release
artifact hashes or establish that a supplied uncertainty model is calibrated.

Transforms follow `parent_T_child`: they map child coordinates into parent
coordinates. Map coordinates are ENU metres; body coordinates are FRD; camera
coordinates are optical right/down/forward. The arbitrary local frame starts
aligned with the initial body, so **raw local coordinates are not ENU**.

Each JSONL event has `type`, positive integer `timestamp_ns`, and
`received_timestamp_ns` in the same clock. Receipt times cannot decrease and
measurement times cannot exceed receipt time. Event types:

- `start`: defines the first local keyframe; permitted exactly once.
- `odometry`: requires `from_timestamp_ns`, `previous_body_T_body`,
  `covariance`, `metric_scale_verified: true`, and VIO/calibration/clock/noise IDs.
  It must connect the latest keyframe to a strictly newer one without an
  excessive gap. Increments must have qualified independent process noise;
  differencing correlated posterior VIO/PX4 poses is not sufficient.
  GNSS-aided PX4 local position must not be relabeled as independent GNSS-denied
  odometry, nor may previous vision corrections return as fresh local evidence.
- `map_fix`: requires `fix_id`, `map_T_camera`, `covariance`, map/model/
  calibration/clock/noise IDs, `geometry_mode: pnp_3d`,
  `hypothesis_state: unique_temporal_support`, and integer `temporal_support >= 2`.
  These flags are upstream attestations, not evidence generated by this smoother.
  One map fix per retained keyframe is allowed. Duplicate IDs in the active
  window are rejected; expired timestamps are rejected. The producer must keep
  fix identities unique for the entire session.
- `tick`: advances the observed receipt clock without inventing a measurement.

All factor covariances are finite, symmetric, strictly positive-definite 6x6
matrices with `covariance_convention: right_tangent_rx_ry_rz_tx_ty_tz`:
rotation perturbation radians followed by translation metres. Camera covariance
is transformed through the calibrated lever arm before constructing body factors.
Zero-filled unknown axes, homography-only fixes, future/non-keyframe fixes,
ambiguous hypotheses and unresolved metric scale are rejected.

The common map covariance is a **left** tangent perturbation, rotation-first,
about the declared ENU map frame. It remains a floor across repeated fixes.
It must come from an explicit map-error model; do not insert guessed small values
just to pass validation. Map fixes' conditional measurement noise is assumed
independent after separating this common component.

## Replay And Evidence

With a qualified configuration and recorded factor log:

```bash
vision-nav-replay-estimator \
  --config /data/session/estimator.json \
  --log /data/session/metric-factors.jsonl \
  --output /data/replays/estimator-run-001
```

Outputs are `config.json`, `decisions.jsonl`, and `summary.json`. Every processed
event has an input hash, acceptance/rejection reason and state snapshot. Summary
hashes bind configuration, full processed input, decision trace and implementation
source. Evidence directories cannot be overwritten. Malformed/duplicate JSON
fields and non-finite constants are rejected. Oversized events abort replay with
an incomplete summary; its input hash is null rather than a misleading full hash.
Exit code 2 reports rejected/incomplete/failed or unstarted replay; exit code 0
means successful factor processing, **not navigation readiness**.

States distinguish `NOT_STARTED`, `LOCAL_ONLY`, `SMOOTHED`, `MAP_STALE`,
`LOCAL_STALE`, and `FAULT`. Pose snapshots carry their measurement timestamp,
not a freshly invented timestamp when polled. Stale poses may remain available
for evidence, but never become position authority.

Reported covariance uses joint map/local marginals, including their cross terms,
then adds the common map floor. Output order is ENU translation and small world
rotation perturbations: `map_enu_dx_dy_dz_drx_dry_drz`. These are **not Euler-angle
variances or PX4 NED covariance**. Calibration is explicitly labeled
`unvalidated_linearized_conditional_plus_declared_systematic_floor`.

## Remaining Gates

- No raw image/IMU frontend, IMU bias estimation, initialization or metric-scale
  verification is implemented by this module.
- No spatial multi-hypothesis bank or tile-overlap fusion is implemented here.
  An incorrect first alias can initialize a graph; robust loss cannot prove
  that a visually plausible map is globally correct.
- Learned PnP replay candidates currently have unset covariance and cannot feed
  this interface. Calibration/timing/map uncertainty and real-image residuals
  must first produce and validate a pose-noise model.
- GTSAM marginal covariance is a local linearized approximation. The common map
  floor does not model all shared extrinsic, timing, learned-model or VIO/map
  cross-correlations. No protection level or accepted-fix precision is claimed.
- No live scheduler, velocity/bias publication, continuity policy, MCAP adapter,
  Pi qualification or PX4 transport is added. Outputs stay shadow-only.

The old `VisionFactorGraph` demo compatibility port now always withholds position.
It no longer adds untranslated VO increments, treats a camera pose as a body
pose, or manufactures confidence by repeatedly blending cached map fixes.
Its identity pose is a legacy-schema placeholder, not an estimate. Its older
message types cannot silently opt into this qualified-factor backend.
