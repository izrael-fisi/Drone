# Production sign-in for Global View

Global View hosts the organization and sign-in method picker. Auth0 Universal Login handles email and password, Google, Microsoft, and any enabled GitHub or customer SSO connection. Operators set up an authenticator on first sign-in and complete an authenticator challenge on later sign-ins. Global View checks the signed proof of MFA, the selected connection, and the Auth0 organization before creating a session. The gateway separately enforces the operator's site role and camera scope.

## Configure the identity service

1. Create separate Auth0 staging and production tenants with Universal Login. Confirm the plan supports Organizations, the required connection types, and MFA Actions. Create a **Regular Web Application** with RS256, Authorization Code, and the token endpoint authentication method configured in the private portal file. Register `https://PORTAL_HOST/api/enterprise/callback/ORG_SLUG` for each organization. Set the Application Login URI to `https://PORTAL_HOST/api/enterprise/invite`. [Universal Login](https://auth0.com/docs/universal-login) · [Invitations](https://auth0.com/docs/manage-users/organizations/configure-organizations/invite-members)
2. Add a database connection for email accounts. Add Google, Microsoft, and any other approved connection with production provider credentials and their exact Auth0 callback. For a customer work tenant use its tenant-specific enterprise connection. Restrict production access with Auth0 Organizations and explicit membership. Disable public signup and automatic organization membership. For an invited database user, precreate the account and use the identity provider's password setup workflow where the tenant's invitation settings require an existing account. Configure the identity provider's transactional email for invitations, verification, and recovery. [Organization connections](https://auth0.com/docs/manage-users/organizations/configure-organizations/enable-connections) · [Social providers](https://auth0.com/docs/authenticate/identity-providers/social-identity-providers)
3. Enable **One-time Password (OTP)** and **Customize MFA Factors using Actions**. Attach the two Post Login Actions to the Login flow in this order. First deploy `require-authenticator.cjs`. Then deploy `attest-authenticator.cjs`. Set `GLOBAL_VIEW_CLIENT_ID` on both Actions to the Regular Web Application's client ID. Configure the tenant's general MFA policy so this flow drives the Global View challenge. Exercise enrollment and repeat sign-in in staging and use the provider's verified admin recovery procedure to reset a lost authenticator. [MFA selection](https://auth0.com/docs/secure/multi-factor-authentication/customize-mfa/customize-mfa-selection-universal-login) · [Proof after a challenge](https://support.auth0.com/center/s/article/using-actions-mfa-authentication-method-is-missing-on-first-login)
4. Copy `portal.example.json` into private deployment configuration and populate it from the secret store. Keep `production` set to `true`. Use each Auth0 **organization ID** (`org_…`) as `directoryTenant` in the portal and gateway roster. Set `auth0Connections` to the actual connection names allowed for that organization. Supported picker keys are `email`, `google`, `microsoft`, `github`, and `sso`. Omit unavailable choices. Each organization can use the same issuer and web application with its own organization ID and callback. [Auth0 organization token checks](https://auth0.com/docs/manage-users/organizations/using-tokens)

## Enroll operators and verify the release

Use the Auth0 organization invitation workflow for approved members. Provision their stable Auth0 user ID from the identity provider as the `subject` in Global View's site roster, with the required role and camera scope. Password and social accounts with the same email are separate identities. Site access attaches to the approved subject. Use a new gateway state directory for a new organization binding, or plan that migration separately for an existing site's data and memberships.

Run the existing enterprise portal behind the production HTTPS terminator. Keep the gateway listeners private. Omit callback and invitation query strings from access logs. When offboarding an operator, disable their Global View site membership and remove their Auth0 membership. The gateway checks membership on each protected request, including recordings.

Verify one invited email account, one Google account, and one Microsoft account. Complete first-time MFA enrollment and repeat sign-in. Check password reset, lost-authenticator recovery, direct cross-organization access rejection, and sign-out. A missing, stale, or wrong-connection MFA attestation must leave the browser signed out. Test with the real production provider registrations before granting customer access. Existing direct OIDC pilots can continue with their current development configuration. Portal sessions created before this update require a fresh sign-in after migration.
